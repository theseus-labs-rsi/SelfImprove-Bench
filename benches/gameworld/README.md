# RSI-Bench CSD + GameWorld alignment notes

## Goal

This directory integrates GameWorld as a native benchmark of RSI-Bench CSD. The overall
execution chain matches the CSD built-ins `farm`, `combat`, `heros_journey`, and
`sweepmine`:

```text
benchmark runner
  -> benchmark.tasks / task_manifest
  -> benchmark.game_adapters
  -> benches.gameworld.GameWorldBenchmark
  -> GameWorld main.py
  -> GameWorld BaseClient wrapper
  -> ACE / HyperAgents / AHE CSD agent
  -> GameWorld evaluator
```

GameWorld therefore does not start a separate experiment entry point outside CSD; it
shares task orchestration, training/refinement, candidate validation, holdout
evaluation, result aggregation, and error semantics with the other CSD benchmarks.

## Current game scope

The current configuration selects two games that share one GameWorld core:

| Category | Game | Training tasks | Holdout tasks |
|---|---|---|---|
| Exploring | `18_minecraft-clone-glm` | 20 training tasks, plus 6 reserved hard task assets | 5 original holdout tasks |
| Exploring | `03_astray` | 20 seed-parameterized training tasks | 5 original holdout tasks |

Training and holdout tasks are listed explicitly in the configuration; they are not
randomly generated by numeric difficulty, and train/holdout overlap is not allowed.

## Installing dependencies

In the Python environment that runs the benchmark, run from the `code` directory:

```powershell
python -m pip install --upgrade -e ./benches/gameworld/assets/core/code --only-binary=greenlet,pillow,pyzmq,cryptography
python -m playwright install chromium
```

GameWorld dependencies are declared centrally in `assets/core/code/pyproject.toml`;
its `requirements.txt` references that declaration via `-e .` and must be used from the
directory that contains the file. Outer dependencies are still managed by
`code/requirements.txt`. These pins match the environment used for the reported
experiments: CPython 3.13.12 on Linux x64 with Playwright 1.61.0, greenlet 3.5.6,
Pillow 11.3.0 and PyZMQ 27.2.0. After upgrading Playwright, reinstall the
matching Chromium. Install compatibility and benchmark results still need verification.

## The three frameworks

The public code supports three methods at once; framework and model are two independent
dimensions:

| CSD provider | GameWorld client | Input preserved |
|---|---|---|
| `ace` | `ACEGameClient` | original system prompt + short action history + current screenshot + semantic controls |
| `hyperagents` | `HyperAgentsGameClient` | same as above |
| `ahe` | `AHEGameClient` | same as above; if upstream AHE does not yet support images it reports a clear compatibility error |

The corresponding adapters use this repository's unified implementation:

- `rsi_methods.ACE.ACEAdaptor.ACEAdaptor`
- `rsi_methods.HyperAgents.HyperAgentsAdaptor.HyperAgentsAdaptor`
- `rsi_methods.AHE.AHEAdaptor.AHEAdaptor`

In this repository's RSI integration, the API model for the execution and evolution
agents is controlled by each method's `config.toml`. The benchmark JSON controls the
task list, count, seed, game steps, and run orchestration; its `agent.model` does not
override the model settings of these RSI methods. The API key and endpoint are read from
the environment variables named by the method TOML.

`game_options.gameworld.model_spec` is the **ID of a GameWorld catalog configuration
entry**, used to locate `assets/core/code/catalog/models/<ID>.yaml`, which provides the
prompt template, output format, and default client parameters. The GameWorld wrapper
delegates the actual model call to the RSI agent using the execution model from the
method TOML; refinement likewise uses the corresponding evolution model from the method
TOML.

The current `model_spec: "gpt-5.6-sol"` keeps a historical catalog entry for
compatibility with existing client initialization. This ID's name does not mean the
actual RSI request uses GPT, and it need not match the method TOML model name. To switch
to DeepSeek temporarily, change the model setting in the method TOML and keep a usable
GameWorld catalog ID. When `model_spec` is not configured, use the `GAMEWORLD_MODEL_ID`
environment variable to name the catalog ID.

## Configuration and running

The six GameWorld configurations are in `configs/main/` (see
[configs/main/README.md](../../configs/main/README.md)):

- `astray_{ace,ahe,hyperagents}.json`
- `minecraft_{ace,ahe,hyperagents}.json`

By default `assets/core/` is used, and task YAMLs live under `assets/tasks/train/` and
`assets/tasks/holdout/`. An explicit `gameworld_root` takes precedence
over `GAMEWORLD_ROOT`, and the environment variable takes precedence over the built-in
core. When using an external core, provide `task_assets_roots.train` / `holdout`
explicitly. Run from the repository root, for example in PowerShell:

```powershell
$env:OPENAI_BASE_URL = "https://your-openai-compatible-endpoint/v1"
$env:OPENAI_API_KEY = "your-key"
python -m benchmark YOUR_LOCAL_CONFIG.json --max-new-train-runs 1
```

The configuration does not store a key or URL; `api_key_env` / `base_url_env` in the
method TOML names the environment variables to read. The main configurations are
complete experiments (20 train / 5 holdout); for a first check, copy one and reduce the
task counts and `max_steps`. GameWorld run artifacts are stored under each run's `output_dir/gameworld/` and
do not depend on the old launcher initialization. Running requires Playwright and
Chromium; HyperAgents additionally requires a working Docker environment. According to
the manual run log of 2026-10-07, both the minimal training and the holdout evaluation of
Astray + ACE were `status=ok`; the AHE and HyperAgents combinations with Minecraft still
need verification, and step-level recovery was not verified in that smoke run either.
Video replay needs FFmpeg on the system PATH; when it is missing, already-saved
evaluation results are unaffected. When video is not needed, CMD can run
`set GAMEWORLD_DISABLE_VIDEO_REPLAY=1` and PowerShell can run
`$env:GAMEWORLD_DISABLE_VIDEO_REPLAY = "1"`.

When switching frameworks, change both `agent.provider` and
`game_options.gameworld.framework`; an inconsistency is rejected during config parsing so
that a hidden mismatch such as "using AHE refinement while actually running the ACE
client" cannot occur.

## Input, scoring, and results

GameWorld's task prompt, screenshots, short history, semantic action space, and evaluator
are still generated by the original GameWorld catalog/runtime. The CSD adapter does not
additionally expand live structured `game_state` into the user prompt, nor does it change
GameWorld's SR/PG scoring definitions.

Each episode's results preserve:

- the final `progress`, `task_status`, `metrics`, and stop reason in `summary.json`;
- prompts, screenshot paths, model outputs, executed actions, usage, game state, and
  step-wise evaluator results in `interactions.jsonl`;
- the CSD-standard `FeedbackResult` used by ACE/HyperAgents/AHE refinement;
- the CSD runner's `result.json`, per-episode run record, and token/time telemetry.

"Reaching the game objective" and "whether an exception occurred during execution" are
two different concepts: a run that finishes normally without clearing the game is
recorded as `status=ok, success=false`, and only a launch failure, a missing summary, or
a runtime exception is recorded as `status=error`. A failure is never disguised as a
zero-score game result.

## Recovery and integration boundaries

See `benchmark/RESUME.md` for the task-level `--resume` and the existing `--target-dir`.
GameWorld step-level recovery is enabled separately via `resumable_steps=true` or
`RSI_STEP_RESUME=1`; it currently supports Astray / Minecraft and preserves browser
state, model reply evidence, and method sessions. Astray's default seed 42 and original
evaluation rules are preserved; the training YAML uses parameterized seeds. Absolute
paths of checkpoints from before a move and code hashes are not migrated automatically;
start a new experiment directory after changing code.

GameWorld currently only accepts ACE / AHE / HyperAgents. HyperDSH image forwarding and
step recovery are left for a later integration, while the Hero / Sweepmine HyperDSH
integration is retained. Metrics and aggregation follow the current CSD version.
